# 📦 NPM 依赖下载和内网发布完整指南

## 🎯 功能说明

本方案实现了从 [package.json](file://c:\Users\Admin\Desktop\前端AI\npm发布\npm-install\package.json) 自动读取依赖列表，**从公网下载所有依赖**（包括完整依赖链），并发布到本地 Verdaccio 仓库，供内网机器使用。

## 🔄 完整工作流程

```
┌─────────────────────┐
│  package.json       │ ← 读取依赖列表
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  npm install        │ ← 从公网 npmjs.org 下载
│  (registry.npmjs.org)│    （因为本地 Verdaccio 还没有）
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  node_modules       │ ← 扫描所有已安装的包
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  offline-packages   │ ← 同步到离线目录
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  npm publish        │ ← 发布到本地 Verdaccio
│  (localhost:4873)   │    （现在本地有了这些包）
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  内网机器            │ ← 配置 registry 后直接从本地下载
│  npm install xxx    │    （无需访问公网）
└─────────────────────┘
```

## 💡 关键说明

### 为什么需要从公网下载？

**首次执行时**，本地 Verdaccio 仓库是空的，没有任何包。因此：
- ✅ **下载阶段**：必须从公网 npmjs.org 下载
- ✅ **发布阶段**：再发布到本地 Verdaccio
- ✅ **内网使用**：内网机器从本地 Verdaccio 下载（无需公网）

### 二次执行时的优化

当某些包已经在 Verdaccio 中时：
- 脚本会**自动检测并跳过**已存在的包
- 只下载和发布新增的包
- 符合用户偏好：**绝不覆盖已存在的包**

## 🚀 快速开始

### 前置条件

1. ✅ Node.js 已安装
2. ✅ Verdaccio 服务正在运行
3. ✅ **网络连接正常**（首次下载需要访问公网 npmjs.org）

### 一键执行

**方式 1：使用批处理脚本（推荐）**
```bash
download-and-publish.bat
```

**方式 2：使用 npm 命令**
```bash
npm run download-and-publish
```

### 执行步骤详解

脚本会自动完成以下 5 个步骤：

#### 步骤 1/5: 读取 package.json 中的依赖
- 读取 `devDependencies` 中的所有包
- 显示找到的所有主依赖（约 22 个）

#### 步骤 2/5: 从公网下载所有依赖（包括完整依赖链）
- **关键点**：从 `https://registry.npmjs.org` 下载
- 对每个主依赖执行 `npm install`
- 自动递归下载所有子依赖（预计约 100+ 个包）
- 使用 `--legacy-peer-deps` 避免冲突

#### 步骤 3/5: 扫描 node_modules 获取完整依赖树
- 递归扫描 `node_modules` 目录
- 识别所有已安装的包（包括深层依赖）
- 去重处理，避免重复
- 限制深度为 5 层

#### 步骤 4/5: 同步包到离线目录
- 将所有包复制到 `offline-packages/` 目录
- 已存在的包自动跳过
- 保留完整的 package.json 和文件结构

#### 步骤 5/5: 发布到本地 Verdaccio 仓库
- 检查包是否已存在（HTTP HEAD 请求）
- **已存在的包自动跳过**（不会覆盖）
- 发布新包到 `http://localhost:4873`
- 捕获 E409 错误作为二次确认
- 生成详细的发布报告

## 📋 配置说明

### 两个 Registry 的作用

在 [`scripts/download-and-publish.js`](file://c:\Users\Admin\Desktop\前端AI\npm发布\npm-install\scripts\download-and-publish.js) 中定义：

```javascript
const LOCAL_REGISTRY = 'http://localhost:4873';      // 本地 Verdaccio（用于发布）
const PUBLIC_REGISTRY = 'https://registry.npmjs.org'; // 公网 npm（用于下载）
```

**使用场景：**
- **下载时**：使用 `PUBLIC_REGISTRY`（从公网获取包）
- **发布时**：使用 `LOCAL_REGISTRY`（发布到本地）

### Verdaccio 配置

当前配置位于 [`verdaccio/config.yaml`](file://c:\Users\Admin\Desktop\前端AI\npm发布\npm-install\verdaccio\config.yaml)：

```yaml
storage: ./storage
uplinks:
  npmjs:
    url: https://registry.npmjs.org/
    
packages:
  '@*/*':
    access: $all
    publish: $authenticated
  '**':
    access: $all
    publish: $authenticated
```

**关键配置说明：**
- `access: $all` - 允许匿名访问（内网机器无需登录）
- `publish: $authenticated` - 发布需要认证
- `proxy: npmjs` 已注释 - 不从上游获取，避免 E503 错误

### 修改发布地址

如果需要发布到其他 Verdaccio 实例，修改 [`scripts/download-and-publish.js`](file://c:\Users\Admin\Desktop\前端AI\npm发布\npm-install\scripts\download-and-publish.js) 中的：

```javascript
const LOCAL_REGISTRY = 'http://localhost:4873'; // 修改为你的地址
```

## 💻 内网机器使用方法

### 配置步骤

在内网机器上执行：

```bash
# 1. 配置 npm registry 指向本地 Verdaccio
npm config set registry http://<服务器IP>:4873

# 例如：
npm config set registry http://192.168.1.100:4873

# 2. 验证配置
npm config get registry

# 3. 测试安装
npm install lodash
```

### 三种配置方式

**方式 1：全局配置（推荐）**
```bash
npm config set registry http://<服务器IP>:4873
```

**方式 2：项目级配置**
在项目根目录创建 `.npmrc` 文件：
```
registry=http://<服务器IP>:4873
```

**方式 3：临时使用**
```bash
npm install lodash --registry=http://<服务器IP>:4873
```

## 🔧 常见问题

### 1. 下载失败：无法访问 npmjs.org

**症状：**
```
✗ package-name@x.x.x 下载失败
npm ERR! code ENOTFOUND
```

**原因：**
- 没有网络连接
- 防火墙阻止访问
- DNS 解析失败

**解决：**
```bash
# 测试网络连通性
ping registry.npmjs.org

# 检查代理设置
npm config get proxy

# 清除缓存后重试
npm cache clean --force
npm run download-and-publish
```

### 2. Verdaccio 服务未启动

**症状：**
```
Error: connect ECONNREFUSED 127.0.0.1:4873
```

**解决：**
```bash
# 启动 Verdaccio
npm start

# 或者在新窗口运行
start.bat
```

### 3. 发布失败

**症状：**
```
✗ package-name@x.x.x 发布失败
```

**可能原因：**
- 认证失败
- 包名或版本冲突
- 网络问题

**解决：**
```bash
# 登录 Verdaccio（如果需要认证）
npm login --registry=http://localhost:4873

# 查看详细错误信息
npm publish --registry=http://localhost:4873 --verbose
```

### 4. 内网机器无法连接

**症状：**
```
npm ERR! code ECONNREFUSED
npm ERR! errno ECONNREFUSED
```

**解决：**
1. 确认 Verdaccio 服务正在运行
2. 检查防火墙设置，允许 4873 端口
3. 确认 IP 地址正确
4. 测试连通性：
   ```bash
   telnet <服务器IP> 4873
   ```

### 5. 包不存在

**症状：**
```
npm ERR! 404 Not Found - GET http://<IP>:4873/package-name
```

**解决：**
1. 确认包已成功发布到 Verdaccio
2. 访问 `http://<IP>:4873` 查看已发布的包列表
3. 重新运行发布脚本

## 🔒 安全建议

### 1. 启用认证

如果需要在公网访问，建议启用认证：

修改 `verdaccio/config.yaml`：
```yaml
packages:
  '**':
    access: $authenticated  # 改为需要认证
    publish: $authenticated
```

创建用户：
```bash
npm adduser --registry=http://localhost:4873
```

### 2. 配置 HTTPS

在生产环境中，建议使用 HTTPS：

1. 配置反向代理（Nginx/Apache）
2. 使用 SSL 证书
3. 更新 registry 地址为 `https://...`

### 3. 定期备份

定期备份以下目录：
- `verdaccio/storage/` - 包存储
- `offline-packages/` - 离线包
- `packages/` - 元数据

## 🎯 最佳实践

### 1. 首次部署流程

```bash
# 1. 在外网环境下载所有依赖并发布到本地 Verdaccio
download-and-publish.bat

# 2. 打包离线目录（可选，用于传输到其他服务器）
tar -czf offline-packages.tar.gz offline-packages/

# 3. 传输到内网服务器
scp offline-packages.tar.gz user@internal-server:/path/to/

# 4. 在内网服务器解压并启动 Verdaccio
tar -xzf offline-packages.tar.gz
npm start

# 5. 内网机器配置 registry
npm config set registry http://internal-server:4873
```

### 2. 增量更新

当 [package.json](file://c:\Users\Admin\Desktop\前端AI\npm发布\npm-install\package.json) 中添加新依赖时：

```bash
# 只需运行一次脚本
npm run download-and-publish

# 脚本会自动：
# - 检测新依赖
# - 只下载新增的包
# - 跳过已存在的包（绝不覆盖）
# - 发布新包到 Verdaccio
```

### 3. 多版本管理

对于需要多个版本的包（如 minimatch）：

```bash
# 在 package.json 中指定具体版本
"devDependencies": {
  "minimatch": "3.0.4"
}

# 脚本会按指定版本下载和发布
```
